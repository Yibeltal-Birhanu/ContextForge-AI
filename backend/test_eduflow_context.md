# 1. Project Overview

## Project Summary

EduFlow is a monolithic web-based Learning Management System (LMS) designed for Ethiopian universities. It enables students, instructors, and administrators to manage courses, course materials, assignments, quizzes, grades, enrollments, departments, users, and platform settings. The system delivers in-app and email notifications, enforces role-based access control, and is packaged as Docker containers orchestrated via Docker Compose. It uses an ASP.NET Core Web API backend with Entity Framework Core and SQL Server, and a React/TypeScript single-page application frontend.

## Problem

Ethiopian universities need a centralized digital platform to handle course delivery, student enrollment, assignment submission and grading, quizzes, grade reporting, and communication between students, instructors, and administrators. EduFlow addresses this need with a single integrated system tailored to the Ethiopian university context.

9. FR-009: Assignment Grading by Instructors - Instructors can view student submissions for their courses, assign a grade and feedback, and make grades visible to the submitting student.

# 4. Architecture

EduFlow is a monolithic two-tier web application. The backend is an ASP.NET Core Web API in C# following a layered architecture (Controllers, Services, Repositories) using Entity Framework Core against SQL Server. Authentication uses JWT bearer tokens with role-based authorization policies. The frontend is a React/TypeScript single-page application built with Vite, using Axios for API calls and React Router for navigation. The solution is packaged as Docker containers orchestrated by Docker Compose: an API container, a frontend container served by Nginx, and a SQL Server container. File uploads are stored on a Docker volume mounted into the API. Email notifications are sent via MailKit (SMTP) and in-app notifications are persisted and exposed through a notifications API. A logical multi-tenant strategy uses a TenantId column on tenant-scoped entities. Audit logging captures sensitive admin actions in a dedicated table.

# 8. Security Requirements

- Authentication: Issue short-lived JWT access tokens (e.g., 60 minutes) signed with a strong secret stored in environment configuration; include role and user id claims; require a valid token on all protected endpoints.
- Password Storage: Hash all passwords with BCrypt before persisting to the database; never store, log, or transmit plaintext passwords.
- Authorization: Enforce ASP.NET Core role-based policies ([Authorize(Roles = "Administrator")], etc.) at the controller level, and perform resource-level ownership/enrollment checks inside services (e.g., an instructor can only modify their own courses; a student can only access their own enrollments and submissions).
- Transport Security: Terminate TLS at a reverse proxy (Nginx) in production and force HTTPS redirects to protect JWT tokens and user data in transit.
- Input Validation: Validate all incoming DTOs with FluentValidation at the controller boundary; reject malformed or malicious input before it reaches services or the database.
- CORS: Restrict API CORS to the configured frontend origin only to prevent unauthorized browser clients.
- File Access Control: Serve all uploaded files only through authorized API endpoints that verify the caller's enrollment or ownership before streaming the file; never expose the underlying file path publicly.
- Audit Logging: Record all user management, department management, and platform setting changes in the AuditLog table with acting user, timestamp, and action details, and expose them through the audit-logs API for administrators.
- Tenant Isolation: Include a TenantId on tenant-scoped entities (User, Department, Course, etc.) and filter queries by the authenticated user's tenant to enable safe multi-university deployment.
- Error Handling: Return generic error messages for authentication failures; do not leak sensitive information about users, passwords, or internal configuration in API responses or logs.
